# 日本の町並みプロシージャル生成 — 拡張候補と実装優先度

対象コードベース: `house-gen`

## 1. 目的と対象範囲

本書は、現在実装済みの戸建住宅・集合住宅・ロードサイド店舗・敷地外構・踏切を土台として、日本の町並みとしての密度と説得力を上げるための拡張候補を整理したロードマップである。

道路本体、道路標識、電柱は当面の検討対象外とする。数値寸法や法規条件を確定する資料ではなく、今後どの生成要素を調査・設計するかを決めるための候補一覧として扱う。

## 2. 現在の実装範囲

現時点では、主に次の要素が存在する。

- 戸建住宅: フットプリント、階層別マス、ファサード、屋根、バルコニー
- 戸建外構: 駐車、アプローチ、庭、犬走り、植栽帯、塀、門、カーポート
- 戸建プロップ: 車、物置、室外機、自転車、樹木、低木
- 集合住宅: 住戸配列、共用廊下、階段・EVコア、外構、駐車・駐輪、ゴミ置場
- 集合住宅プロップ: 駐輪場、メールボックス、ベンチ、照明、植栽など
- ロードサイド店舗: 店舗建物、駐車場、サービスヤード、看板、店舗外構
- 店舗プロップ: 車、トラック、カート置場、照明、自販機、旗、充電器など
- 公共空間の試作: 車道、歩道・路肩、側溝、路面標示、電柱
- 鉄道環境: 踏切設備

したがって次の段階では、大型の新規建物を増やすだけでなく、敷地の高低差、生活設備、土地利用の混在、施工年代の差を追加することが重要になる。

## 3. 優先度A: 敷地境界と高低差

住宅地を単なる平面上の建物配置に見せないため、最優先で検討する。

### 3.1 候補

- コンクリート擁壁
- 化粧ブロック塀、万年塀、低いコンクリートブロック＋アルミフェンス
- 敷地ごとの宅盤高
- 道路から玄関までの階段・スロープ
- 駐車場入口の切り下げ
- 法面、石積み
- グレーチング、雨水桝、暗渠蓋
- 細い開渠、水路、用水路
- 境界杭、境界ブロック

### 3.2 生成上の考え方

敷地に単一の `baseZ` を持たせるだけでなく、道路高、宅盤高、建物基礎高を分離する。高低差が閾値を超えた境界に擁壁を発生させ、玄関・駐車・サービス動線には階段、スロープ、切り下げを接続する。

古い石積みの上に新しい住宅が建つような状態を表現できるよう、建物と境界工作物の施工年代は独立させる。

## 4. 優先度A: 住宅の生活感と付帯設備

小さな要素だが、近景での情報量と居住感に大きく寄与する。

### 4.1 建物付帯設備

- 軒樋、竪樋
- 電気・ガス・水道メーター
- 給湯器、エコキュート、プロパンボンベ
- テレビアンテナ、BSアンテナ
- 表札、インターホン、郵便受け、宅配ボックス
- 雨戸、シャッター、面格子
- 窓のカーテン、ブラインド

### 4.2 屋外生活物

- 物干し竿、洗濯物、布団
- ホースリール、じょうろ、植木鉢、プランター
- ゴミ箱、収納ケース、脚立
- 子供用自転車、原付、ベビーカー
- 駐車場の輪止め、チェーンポール

### 4.3 生成上の考え方

建物形状を決めるパスとは分け、完成した壁面、開口、屋根、サービスヤードを入力とする `ResidentialDetailPass` のような付帯物配置段を設ける。

配置は完全な散布ではなく、意味のあるアンカーに従わせる。

- メーター・給湯器・室外機: サービス面または側面
- 表札・インターホン・郵便受け: 門から玄関までの動線沿い
- 物干し・布団: 日照側のバルコニーまたは庭
- アンテナ: 屋根または上階壁面
- 植木鉢・生活用品: 玄関脇、勝手口、テラス、物置周辺

## 5. 優先度B: 小規模用途と土地利用の混在

戸建、集合住宅、大型店舗の間を埋め、同じ建物が連続する単調さを崩す。

### 5.1 建物・敷地用途候補

- 木造アパート
- 住宅兼店舗
- 個人商店、理美容室、クリーニング店
- 町工場、自動車整備工場
- 小規模診療所、歯科
- コンビニ
- コインランドリー
- 月極駐車場、コインパーキング
- 倉庫、貸しガレージ
- 空き家、解体待ち住宅
- 空き地、資材置場
- 農地、家庭菜園が残った区画

### 5.2 初期実装に向く用途

次の用途は複雑な建物生成器を新設せず、既存コンポーネントの組合せで実現しやすい。

- 月極駐車場: 既存の駐車列、車路、フェンス、看板基部を再利用
- 空き地: 地表ゾーン、雑草、仮囲い、資材の配置
- 住宅兼店舗: 戸建マス＋1階街路面の店舗ファサード
- 町工場・貸しガレージ: 単純な箱型マス＋大開口シャッター＋作業ヤード

土地利用は `ParcelUse` のような上位属性として扱い、個々の建物ジェネレーターを選択する前に決定する。

## 6. 優先度B: 道路設備以外の公共・共同要素

- ゴミ集積所、防鳥ネット
- 自治会掲示板
- 消火器ボックス
- 防火水槽マンホール、設備箱
- 公衆電話ボックス
- 郵便ポスト
- 小規模な児童公園
- ベンチ、砂場、滑り台、鉄棒
- 集会所
- 地蔵、祠、小さな神社
- 寺院、墓地の外周
- 河川・水路沿いの柵
- 鉄道沿いの防音壁、架線設備、線路脇の機器箱

ゴミ集積所や自治会掲示板は、複数敷地に共有される要素として、各 lot の内部ではなく block または街区単位で配置する。

## 7. 優先度B: 植生と季節

現在の `tree` / `shrub` を、樹種、配置理由、管理状態へ拡張する。

### 7.1 候補

- 生垣
- 庭木: 松、モミジ、キンモクセイなど
- 鉢植え、プランター
- 街角や空き地の雑草
- 越境した枝
- 剪定された木、放置された木
- 落ち葉、苔、土汚れ
- 家庭菜園
- 桜、紅葉、積雪などの季節状態

### 7.2 配置規則

ランダム散布ではなく、前庭、境界沿い、日照側、目隠しが必要な面、放置区画など、場所の役割から植生タイプを決める。季節は個々の植物ではなく、シーン全体の状態として解決する。

## 8. 優先度A〜B: 経年変化と地域差

新しい形状を増やすだけでなく、既存の生成物へ状態差を加える。

### 8.1 経年状態

- 築年帯: 昭和、平成前期、平成後期、令和
- 外壁の退色、雨垂れ、錆、苔
- 増築、後付けバルコニー、後付けカーポート
- 屋根または外壁だけ改修済み
- 古い塀と新しい建物の組合せ
- 空室、閉店、シャッター常閉

建物、屋根、外壁、塀、外構、設備に別々の施工年代または更新状態を与え、すべてが同時に新品になる状態を避ける。

### 8.2 地域プリセット

- 都市部、郊外、地方住宅地
- 平地、丘陵地、豪雪地
- 都市ガス地域、プロパン地域
- 駅周辺、幹線道路沿い、旧集落

地域プリセットは個別オブジェクトを直接指定するのではなく、宅盤高、敷地面積、駐車需要、屋根形式、植生、設備、土地利用構成などの確率分布を束ねる。

## 9. 町並み全体の生成規則

最終的な町並みの説得力は、単体アセットよりも隣接関係と履歴から生まれる。

- 区画の細分化、合筆
- 古い大区画内にまとまって建つ新築分譲住宅
- 角地への店舗配置
- 駅や幹線道路からの距離に応じた用途変化
- 同時期に建った建売住宅のまとまり
- 建物年代の空間的クラスタ
- 駐車台数と世帯構成の相関
- 隣家同士で向かい合う窓を避ける配置
- 日照方向によるバルコニー、物干し位置
- 地形に沿った擁壁と宅盤高
- 空き地、駐車場、新築へ移る更新状態

この段階では、各 lot を完全に独立生成するのではなく、先に街区コンテキストを生成し、それを各敷地の条件として渡す必要がある。

想定するコンテキスト例:

```ts
interface BlockContext {
  terrainProfile: TerrainProfile;
  neighborhoodType: NeighborhoodType;
  developmentEra: DevelopmentEra;
  season: Season;
  sharedFacilities: SharedFacility[];
  parcelRelations: ParcelRelation[];
}
```

具体的な型名と所属ディレクトリは、街区生成パイプラインを設計する段階で確定する。

## 10. 推奨実装順

### Phase 1: 宅盤と境界

`TerrainParcelPlan` 相当を追加し、道路高、宅盤高、擁壁、階段、スロープ、水路を扱う。既存の建物・外構を大きく変更せず、町並みの立体感を改善できる。

### Phase 2: 住宅付帯物

`ResidentialDetailPass` 相当を追加し、雨樋、メーター、給湯器、郵便受け、物干しなどを、既存のファサードと敷地動線から決定論的に配置する。

### Phase 3: 土地利用バリエーション

`ParcelUse` を追加し、月極駐車場、空き地、住宅兼店舗、町工場を生成対象に加える。初期段階では既存の戸建・店舗・駐車コンポーネントを再利用する。

### Phase 4: 年代・地域・季節

施工年代、更新状態、地域プリセット、季節を追加し、形状、マテリアル、植生、生活物の確率分布へ反映する。

### Phase 5: 街区コンテキスト

区画の履歴、隣接関係、共有設備を街区単位で生成し、各 lot ジェネレーターへ制約として渡す。

## 11. 実装時に維持する規約

- 生成ロジックは Three.js 非依存の純 TypeScript とする
- 同一 seed と入力から同一結果を返し、`Math.random()` は使わない
- tunable は各生成領域の config に集約する
- 建物、敷地、街区の責務を分離する
- プロップの種類だけでなく、配置理由をデータとして表現する
- 新しいアセットを置く前に、衝突、動線、敷地内包、境界距離を純ロジックで検証する
- 車、植物、生活小物、テクスチャは外部アセットを利用してよい
- 建物の壁、開口、屋根、付帯形状は可能な限りプロシージャルに生成する

## 12. 当面の結論

次に着手する候補は、次の3本を優先する。

1. 宅盤高、擁壁、階段、スロープ、水路を扱う敷地地形パス
2. 雨樋、メーター、給湯器、郵便受け、物干しを扱う住宅付帯物パス
3. 月極駐車場、空き地、住宅兼店舗、町工場を扱う土地利用選択

これらは新しい大規模建物ジェネレーターを増やすよりも既存コードを再利用しやすく、町並み全体の情報量、生活感、年代差をまとめて改善できる。
